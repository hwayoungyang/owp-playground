Core JSON 결과 표시 (2026-10-27): 비교 표의 JSON은 기존 --font-mono·12px/1.6·2칸 들여쓰기와 왼쪽·위쪽 정렬을 사용한다. JSON 문자열은 표시용으로만 파싱하며 원본 반환값·상태·이벤트는 유지한다. 긴 내용의 가로 스크롤은 표 안에서 소유한다.

Core 분류와 링크·입력 배치 (2026-10-27): 실행 메뉴는 Hooks·Utils·UI Adapter의 공개 API 형태로 구분하고 FormData hook과 ZIP 유틸은 별도 메뉴로 제공한다. 안내 문서 링크는 기존 --pg-blue와 밑줄·focus-visible을 사용한다. 입력 필드의 240px flex-basis는 가로 control 행에만 적용하고 세로 본문 필드에는 고정 높이로 적용하지 않는다. 신규 화면도 기존 PreviewToolbar·16px 간격·실제 표 body·공통 CodeViewer를 재사용한다.

Core 공개 기능 보완 (2026-10-27): Core가 직접 구현한 hooks·utils·진단 기능을 공개 entry point와 원본 구현으로 확인하고 요청 데이터 변환·파일 데이터 준비와 ZIP·API Inspector·영역별 미저장 보호·로그인 입력값 정리를 실행 예제로 보완한다. 다른 패키지의 re-export·UI 자체 기능·내부 구현 전용 API는 새 Core 메뉴에서 제외한다. 실행 예제는 기존 CoreDemo·Controls·결과 표·CodeViewer를 재사용하며 실제 서버가 필요한 동작은 필요한 계약을 문서로 설명한다. 기능 안내에서 Core 역할별 공개 API와 해당 문서·실행 메뉴를 연결한다.

버튼과 안내 문구 (2026-10-27): 결과 영역의 시작 안내는 실제 버튼 이름을 사용한다. 검색 버튼은 “검색 버튼을 눌러 주세요.”로 안내하고 조회 버튼이 있는 예제만 조회라고 안내한다. 공개 한국어는 문맥에 따라 앱·프로젝트·앱 구성 예시를 사용한다. Core 시작하기도 기존 공통 MCP 안내를 재사용해 연결·버전 고정·API와 가이드·예제 조회 방법을 제공한다.

메뉴와 API 로딩 (2026-11-02): WorkspaceLoading은 본문 전체 또는 내부 패널의 가운데에 로딩 상태를 표시한다. 기존 13px 본문·16px 간격·blue/secondary 테마 색상과 MUI의 32px 원형·160px 너비의 3px 선형 indeterminate progress를 사용한다. 진행률을 임의로 표시하거나 표시를 위해 완료를 늦추지 않는다. 한 개의 status가 상태를 알리고 장식 progress는 접근성 트리에서 숨긴다. reduced-motion에서는 진행 애니메이션을 중지한다. API 목록은 공통 요약 데이터를 사용하고 상세 선언·Props·Signature·예제는 선택한 API가 속한 64KiB 이하 묶음으로 나눠 지연 로딩한다. 이 크기를 초과하는 단일 API는 내용을 자르지 않고 별도 묶음에 보존한다. 기존 URL·번역 key·API 내용·예제 상태와 Knowledge·MCP·스냅샷 경계를 유지한다.

# OWP Playground Design System

전체 공개 API 탐색 (2026-10-31): 설치된 패키지의 루트·subpath 공개 export를 하단 공개 API 그룹에서 탐색한다. 컴포넌트·Hooks·Utils·Context·Constants·Values·Types·파일을 구분하고 항목이 없는 분류는 숨긴다. 기존 WorkspaceHeading, MUI Tabs, API 표, CodeSnippet, PlaygroundLink와 테마 토큰을 재사용한다. 실제 실행 화면은 예제·코드에 API 종류별 Props 또는 Params·Returns·Type을 추가한다. 공개 API 상세는 코드와 종류별 계약 탭을 제공하며 같은 스니펫을 예제 탭에 반복하지 않는다. 관련 실행 예제가 있으면 원본 CodeViewer와 예제 보기 링크를 사용한다. 현재 패키지의 선언 출처는 반복하지 않고 re-export·상속에 필요한 출처만 표시한다. 짧은 API 설명은 명사형과 마침표로 통일하고 사용 안내 본문은 합니다 문체를 사용한다. 버전은 상단 패키지 영역, 전체 개수는 사이드바 하단에만 표시한다. 코드·Props에 중복된 원문 선언 펼치기를 두지 않으며 함수 시그니처·반환 타입·타입 정의는 각각 Params·Returns·Type에 표시한다. overload·union·상속 출처를 보존하고 표와 코드는 내부 가로 스크롤, 메인은 세로 스크롤을 소유한다. 본문은 desktop 24px/mobile 16px 안쪽 여백과 16px 간격을 따른다. 탭에 키보드 이동·focus-visible·tabpanel 연결을 제공하고 언어·light/dark와 기존 예제의 상태를 보존한다. 화면 projection은 설치본에서 읽으며 Knowledge·MCP·스냅샷과 별도로 관리한다.

공통 문서·예제 문구 (2026-10-30): Components와 같은 용어 기준을 Core·DataGrid·Charts의 메뉴·가이드·예제 설명·공통 API 화면에 적용한다. 일반 설명은 조사와 서술어를 갖춘 문장으로 작성하며 “확인 가능.”처럼 끊지 않는다. 제목·표의 짧은 항목명과 기술 식별자는 형식에 맞게 유지한다. 함수의 매개변수와 HTTP 요청 파라미터처럼 문맥이 다른 개념은 일괄 치환하지 않는다. import 문 자체로 의미가 분명한 API 구간에는 중복된 한국어 제목을 붙이지 않고 코드 블록의 Import 표기만 사용한다. 같은 코드가 “공개 import 경로”라는 제목과 코드 라벨로 반복되지 않게 한다. 상태·오류·저장 시점·허용 조건·미지원 범위와 기존 영어 문서는 보존한다. 패키지에서 읽은 API 원문과 Knowledge·MCP·스냅샷은 별도 반영 요청 없이 수정하거나 재생성하지 않는다.

한국어 API 용어 선정 (2026-10-30): 번역어를 정할 때 최근 한국어 문서 변경이 확인되는 GitHub 저장소의 실제 사용례와 해당 개념의 의미를 대조한다. React 한국어 문서의 [매개변수·반환값](https://github.com/reactjs/ko.react.dev/blob/d9512f30b5c0dbb7780a20a226e763d75dc973b6/src/content/reference/react/useState.md), MDN 한국어 문서의 [함수 시그니처](https://github.com/mdn/translated-content/blob/bae35c2b627cbae91b45fb02625c33dadd09bd79/files/ko/glossary/signature/function/index.md)·[나머지 매개변수](https://github.com/mdn/translated-content/blob/bae35c2b627cbae91b45fb02625c33dadd09bd79/files/ko/web/javascript/reference/functions/rest_parameters/index.md)를 현재 Components API의 기준으로 사용한다. [es-toolkit 한국어 문서](https://github.com/toss/es-toolkit/blob/c55225cb0e8ef31985d35bc9294a86800bd42757/docs/ko/reference/function/debounce.md)의 파라미터·반환 값처럼 저장소마다 표기가 다를 때는 한 화면에서 혼용하지 않는다. 한국어 문서 영역의 최근 변경일은 React 2026-09-30, MDN 2026-10-22, es-toolkit 2026-10-24로 확인했다. 함수 시그니처에는 매개변수와 반환 타입을 보여 준다는 설명을 붙인다. 의미가 다른 개념을 쉬운 표현으로 임의 치환하지 않으며 Props·Type·Required 등 기존 API 계약 표기와 식별자·영문 문서는 보존한다.

Components API 문서 (2026-10-30, 초기 필터 2026-11-02 수정): 문서 그룹의 API에서 컴포넌트·Hooks·Utils 목록과 통합 검색을 제공한다. 처음에는 컴포넌트 목록을 표시하고 항목을 선택하면 해당 API의 import, Props 또는 파라미터·반환값, 관련 타입과 실행 예제를 보여 준다. MUI API 문서처럼 이름·타입·필수 여부·기본값·설명을 표로 읽을 수 있게 하며 타입 분기와 overload의 조건을 보존한다. 상속된 Props는 선언 출처로 구분하고 원문 선언은 접어서 제공한다. 메인 영역의 세로 스크롤을 유지하고 긴 표·코드의 가로 스크롤은 해당 영역이 소유한다. 작은 화면에서는 기존 공간·글자·표면 토큰을 유지하며 검색과 목록을 세로로 배치한다. 선택 항목과 관련 예제는 기존 URL·언어·뒤로 가기를 보존한다. 화면 데이터는 현재 설치된 공개 선언을 앱 빌드 시 읽은 결과만 사용하며 Knowledge·MCP·스냅샷의 생성·등록과 분리한다.

Components 시작하기 (2026-10-30): 메뉴 맨 위의 문서 그룹에 시작하기를 표시하고 Components의 기본 진입 화면으로 사용한다. 기존 사용 예제와 컴포넌트·Hooks·Utils 메뉴의 순서와 기능을 유지한다. 시작하기는 공통 WorkspaceHeading·guide-sections·CodeSnippet·PlaygroundLink를 재사용해 레지스트리 설정, 설치된 버전의 패키지 설치, MUI 테마 설정을 포함한 첫 입력 예제와 공개 import 경로를 안내한다. 가이드와 코드 보기를 기존 URL 규칙으로 연결하며 언어 선택을 보존한다. 새 색상·간격·의존성은 추가하지 않는다.

Components 예제 문서 구성 (2026-10-30): 탐색 메뉴는 상단의 사용 예제와 하단의 컴포넌트·Hooks·Utils로 구분한다. 상단은 주문 입력·검색·상세 조회·미저장 내용 확인처럼 여러 공개 API를 함께 쓰는 화면이다. 하단은 API마다 지원 옵션을 여러 독립 예제로 비교하는 문서다. 각 예제는 ExampleSection의 16px/600 제목, 13px/1.7 설명, 실제 OWP 미리보기로 구성한다. 세로로 나열한 섹션 사이에는 32px 간격과 기존 line 구분선을 사용하며, 한 섹션 안의 비교 입력은 240px 기준 반응형 grid와 16px 간격으로 배치한다. 좁은 화면에서는 한 열로 줄어들며 메인 스크롤 소유권과 기존 코드 탭을 유지한다. 제목·설명·버튼은 대상과 동작을 분명히 쓰고 실제 지원하지 않는 기능을 문구로 약속하지 않는다.

Components 탐색과 실행 (2026-10-29): 설치된 @owp/components의 공개 API를 컴포넌트·Hooks·Utils 세 그룹으로 표시한다. 각 항목은 기존 Sidebar 검색·선택·접기와 URL 탐색을 재사용한다. Preview·Code·Data·Events는 공통 WorkspaceHeading·WorkspaceTabs·PreviewToolbar·CodeViewer·EventsPanel로 구성하며 초기화는 현재 예제의 상태와 이벤트를 함께 비운다. 예제 내부는 기존 MUI·OWP 테마와 16px 간격, desktop 24px/mobile 16px 안쪽 여백을 사용한다. 메인 영역이 페이지 스크롤을 소유하고 긴 표·코드는 자체 가로 스크롤을 사용한다. 문구는 기존 app/owp 번역 리소스에 등록하고 light/dark·영어 전환을 보존한다. Knowledge를 갱신하기 전에는 Components를 API 문서·버전 archive가 완성된 패키지로 표시하지 않는다.

Core 시작하기 가독성 (2026-10-28): 핵심 역할·문서 이름·설정 파일을 본문과 같은 색상의 600 weight strong으로 강조한다. 강조 양옆에는 0.08em 간격을 두고 문단 간격은 20px, 본문 line-height는 1.9로 미세하게 조정한다. 시작하기 본문에만 적용하며 코드·표·목차와 다른 가이드의 간격은 유지한다. API 요청의 성공 결과는 owp·raw 모드 모두 기존 JSON CodeSnippet의 표면·구문 강조·복사 기능으로 표시하고 응답 전체의 원본 JSON 값을 보존한다. 조회 전·오류 상태에는 결과 코드 블록을 표시하지 않으며 요청 상태와 응답 판정 안내를 유지한다. 검색 필터 Skeleton은 기존 core-controls의 줄바꿈과 gap으로 입력 간격을 확보한다.

사용자 권한·조회 상태·공개 명칭 정리 (2026-10-27): 사용자 권한 예제는 셀렉트 선택 즉시 적용하고 샘플 페이지 링크와 CREATE·READ·UPDATE·DELETE를 표로 표시한다. 권한은 semantic success/error 색상의 O/X와 접근성 이름을 함께 제공하며 설명은 한 문단으로 줄인다. 조회 결과 표는 전체 폭의 실제 tbody 영역을 확보하고 조회 전·로딩·결과 없음·오류 안내를 가운데 표시한다. Components 공개 API에 빈 본문 slot이 없으므로 필요한 상태 표만 공개 MUI Table과 OWP 테마로 구성하고 정상 데이터는 OwpTable로 렌더링한다. 회사 상호·로고는 공개 화면·문서에서 제외하고 참조 앱/Reference app으로 일반화한다. 테마 preset은 reference로 저장하되 이전 파일의 preset ID는 import 호환 별칭으로만 읽는다. Core9.0.0·Components3.1.2·Charts5.0.3·DataGrid3.5.2의 설치 공개 API·원본 문서·실행 예제를 대조해 Knowledge 검토 지문을 갱신한다.

Core Components 표 테마 연결 (2026-10-27): Core 실행 환경의 설정 bridge에서 현재 settings.theme.main.table을 공개 OwpThemeProvider.table에 전달한다.
